# 食堂收货拍照编号与双库库存系统

面向食堂早间收货的离线单机系统：**先拍照、按送货单行号编号，再导入送货单自动对应，最后生成食材/非食材双库库存**。

- 不需要联网、不需要安装 Python/Node/npm、不需要管理员权限。
- 数据全部保存在程序目录的 `data\` 下，复制 `data\` 即完成迁移。
- 支持 Windows 10/11 x64；不支持 32 位 Windows、Windows 7、macOS/Linux。

---

## 一、直接使用便携版（推荐）

1. 把 `食堂收货库存系统_便携版.zip` 解压到**可写目录**，例如 `D:\食堂收货库存系统`。
   - 不要放在 `C:\Program Files` 等需要管理员权限的目录。
2. 双击 `启动.cmd`。
3. 浏览器自动打开 `http://127.0.0.1:8765/`；若端口被占用，程序会自动尝试 8766–8775，并在窗口里显示实际地址。
4. 首次使用先到「基础资料」维护收货地点、供应商、品项；到「设置与审计」填写食堂名称和操作员。
5. 停止程序：点网页右上角的 `⏻`，或到「设置与审计 → 运行控制」点「停止服务」；也可以直接关闭黑色命令行窗口。不需要使用键盘快捷键。
6. 页面左侧导航点击后立即切换，不需要刷新浏览器。

> 便携包里已经带了裁剪过的 Python 3.12 运行时。新电脑只要解压即可用；首次运行 Windows SmartScreen 可能提示“未知发布者”，选择“更多信息 → 仍要运行”即可。

## 二、收货流程

### 方式 A：先拍照，再导入送货单（推荐）

1. 进入「收货拍照」，选择收货地点，确认批次时间（默认当前时间，可改）。
2. 每拍一张照片，系统自动新建一行，并编号：
   `地点码-日期-时间-行号`，例如 `01-20261112-073015-01`。
3. 同一种货拍多张时，在对应行点「补拍」，编号自动追加 `-2`、`-3`。
4. 如果拍的时候顺序不对，用「整理行号」调整；批次提交前也可以改时间。
5. 进入「送货单导入」，上传 Excel/CSV，预览并确认品项匹配、分类和数量。
6. 选择刚才的收货批次，提交；照片会按行号自动关联到送货单行。
7. 核对无误后点「提交入库」。提交后编号和单据不可修改，只能作废红冲。

### 方式 B：先导入送货单，再补拍照

1. 先导入送货单，生成待收货单。
2. 进入「收货拍照」，新建批次并拍照。
3. 在送货单详情里把照片关联到对应行；一行可以关联多张。
4. 提交入库。

### 编号规则

```
01-20261112-073015-01
│  │        │      │
│  │        │      └─ 送货单行号（两位）
│  │        └──────── 批次时间 HHMMSS
│  └───────────────── 日期 YYYYMMDD
└──────────────────── 送货地点数字编号（补足两位）
```

同一行第 2、3 张照片：`01-20261112-073015-01-2`、`01-20261112-073015-01-3`。

## 三、送货单导入

支持 `.xlsx`、`.xlsm`、`.csv`；**不支持旧版 `.xls`**（请另存为 `.xlsx`），也不做纸质单/PDF OCR。

- 系统会自动识别常见表头，如「品名/品名及规格」「规格」「单位」「订购数」「实收数/实送数/数量」「单价」「金额」「类别」「生产日期」「保质期」。
- 导入后先预览：可修改行号、品项匹配、类别、数量、单价，再生成送货单。
- 品项匹配顺序：精确匹配 → 别名 → 相似度候选；相似度低于阈值的必须人工确认。
- 无法判断食材/非食材的行会标为“待分类”，必须人工选择后才能提交入库。
- 同一供应商、同一送货单号重复导入会提示重复单，需确认后再继续。

模板可在「送货单导入」页面下载，也可以直接使用自己的表格。

### 手机拍照包（ZIP）

手机端导出的 ZIP 不再走普通 Excel 导入，而是在「送货单导入」页底部的**导入手机拍照包**上传：

- ZIP 里是“修改后的送货单 + 照片/”，由手机端生成；
- 系统按照片名 `地点码-时间-行号[-序号]` 关联到送货行；
- 标为“缺送”的行不入库、不要求照片；其他行必须有 1–5 张照片；
- 同一单号、同一日期重复导入会被拒绝。

## 四、库存管理

- **两个库**：食材库（food）、非食材库（non_food）。
- **收货入库**：提交送货单后按行写入库存流水、余额和批次。
- **领用/报损出库**：按品项领用；有批次时按 FEFO（先到期先出）扣减。
- **盘点**：生成账面快照，录入实盘数，提交后写盘盈/盘亏流水；盘点期间账面数变化会拒绝提交。
- **预警**：低库存、临期、待分类品项、待处理单据。
- **报表**：收货明细、库存余额、库存流水、领用汇总、盘点差异、预警清单，均可导出 Excel。
- **作废**：已入库单据如有后续出库/盘点，系统拒绝直接作废，需按业务先处理；作废采用红冲，不删除历史。

分类和库别可以**勾选多条批量修改**：品项列表、导入预览、送货单行都支持。批量修改会写审计日志；已有库存不会被静默搬到另一个库，需通过盘点/调整处理。

## 五、基础资料的编辑、停用与删除

基础资料不是“只能新增”。品项、送货地点、供应商都支持编辑、停用/启用和删除，但按“历史可追溯”原则分层处理：

- **未被任何单据/库存/盘点引用**：可以删除，删除前会二次确认，并写审计日志。
- **已有历史引用**：系统拒绝删除，返回明确原因和建议；请改用“停用”。停用后不再出现在新单据的选择器中，历史单据、报表、照片编号仍保留。
- **送货地点**：至少保留一个启用地点；已被拍照批次或送货单引用的地点不能删除。
- **供应商**：已被送货单引用的供应商不能删除，只能停用。
- **品项身份**：已有历史送货行的品项，不能修改品名/品牌/规格/单位（否则历史单据会对不上）；可以改分类、库别、安全库存、保质期，或停用后新建品项。
- 删除失败时页面会显示具体原因，例如“送货行 3 条、库存流水 5 条……请改用停用”。

## 六、备份与迁移

- 「设置与审计」里可以一键备份，生成 `data\backups\` 下的数据库/照片压缩包。
- 迁移到新电脑：退出程序，复制整个程序目录（或至少复制 `data\`）到新电脑，再启动。
- 建议每天收货完成后备份一次；备份文件不要只放本机。

## 七、从源码运行/制作便携包

开发机要求：Windows 10/11 x64、Python 3.12 x64，安装 `requirements.txt` 中的依赖。

```bat
python -m pip install -r requirements.txt
python -m app.main
```

制作便携包：

```bat
python tools\build_portable.py
```

输出：

- `dist\食堂收货库存系统_便携版\`
- `dist\食堂收货库存系统_便携版.zip`

构建脚本默认使用当前 Python 运行时；如运行时在别处，可设置 `CANTEEN_RUNTIME` 指向该运行时根目录。

运行测试：

```bat
python -m unittest discover -s tests -v
```

## 八、常见问题

| 问题 | 处理 |
|---|---|
| 双击后窗口一闪而过 | 在命令行运行 `启动.cmd`，查看错误；确认解压目录可写 |
| 浏览器没有自动打开 | 手动打开窗口里显示的地址，通常是 `http://127.0.0.1:8765/` |
| 端口被占用 | 程序会自动换端口；也可编辑 `启动.cmd` 加 `--port 9000` |
| 上传 HEIC 照片失败 | 先转成 JPG/PNG；系统不内置 HEIC 解码 |
| `.xls` 导入失败 | 用 Excel 另存为 `.xlsx` 或 `.csv` |
| SmartScreen 提示 | 未签名程序的正常提示；确认来源后选择“仍要运行” |
| 忘记备份 | 退出程序后直接复制 `data\` 目录也可以 |

## 十、手机拍照端（PWA）

手机端用于收货现场：首次进入先设置**收货地点**和**验收人员** → 导入当天送货单（可多页）→ 逐项改实送数、写备注、标缺送、拍照（每项 1–5 张）→ 完成收货确认 → 导出 ZIP。金额由实送数×单价自动计算，只读，不手工改；导出文件中每行末尾附**收货地点**和**验收人员**。ZIP 通过 U 盘/微信/文件传到电脑，在电脑端「送货单导入 → 导入手机拍照包」入库。

### 方式一：无网站，直接打开离线单文件（最省事）

- 文件：`dist\手机拍照端_离线单文件.html`；把它传到手机（微信/QQ/U 盘/AirDrop/文件 App）后，用 Safari/Chrome 直接打开。
- 不需要网站、不需要服务器、不需要联网；所有代码都在这一个 HTML 里。
- 它不是 PWA：没有 Service Worker、不能“添加到主屏幕”，更新时重新拷一次 HTML。
- **iPhone 限制**：部分 iOS/Safari 版本不允许本地网页长期保存数据；页面会显示“离线单文件模式”警告。请在一轮内完成导入→拍照→导出，导出后立即“存储到文件”，再关闭页面。
- 导出 ZIP 时优先弹出系统分享/存储面板；Android 走浏览器下载。
- 构建：

```bat
python tools\build_offline_html.py
```

输出 `dist\手机拍照端_离线单文件.html` 和同目录使用说明。

### 方式二：HTTPS 静态托管（PWA，可安装/离线缓存）

- **当前已部署：GitHub Pages**：`https://quanyangyang.github.io/canteen-mobile/`。仓库为 public，静态文件在 `main` 分支根目录；更新时替换 `mobile/` 构建产物并等待 Pages 重新发布。
- **备选：Cloudflare Pages**：免费静态托管、自带 HTTPS、`*.pages.dev` 免备案，但国内访问可能被 DNS 污染/阻断；不要把 `workers.dev/pages.dev` 直接当正式入口。
- **备选：Netlify Drop**；国内访问可能不稳定，请用目标手机实测。
- **国内正式长期使用**：阿里云 OSS + CDN、腾讯云 COS + CDN；按量计费，自定义域名通常需 ICP 备案，但国内访问最稳。
- PWA 的 Service Worker 离线缓存和“添加到主屏幕”都要求 HTTPS；局域网 HTTP 只能在线打开，不能完整离线。
- iPhone 用 Safari 15+；Android 用 Chrome/Edge 100+；不要用微信内置浏览器安装。拍照会先请求相机权限；拒绝后可改“从相册选择”，相册一次最多选 5 张。
- 列表里直接点“拍照”会进入该货品并立即打开相机；也可以点卡片进入后选相册。进度和照片会实时写入手机浏览器本地存储，关闭页面前请先导出 ZIP。

### 数据

- 在线版数据保存在浏览器 IndexedDB；离线单文件版在允许时也写 IndexedDB，不允许时只在内存中，关闭页面即丢失；
- 导出 ZIP 后建议立即备份；清空浏览器数据会丢数据；
- 手机端只允许一张送货单（可多页）；检测到多张会拒绝，避免把整月单据混在一起。

构建手机 PWA 包：

```bat
python tools\build_mobile.py
```

输出 `dist\手机拍照端\` 和 `dist\手机拍照端.zip`。
